# Contributing to OIAGP

OIAGP is under controlled candidate development. No contribution is accepted merely because it is submitted.

## Contribution requirements

Contributors must:

1. work only from public OIAGP materials and lawfully usable public standards;
2. avoid confidential, proprietary, employer-owned, client-owned, or restricted material;
3. use synthetic identities, institutions, tenants, resources, and examples;
4. preserve deny-by-default authority, tenant isolation, interruption, revocation, evidence, and human-control requirements;
5. include tests and security analysis for normative changes; and
6. sign commits under the Developer Certificate of Origin 1.1 using `Signed-off-by`.

Submission does not grant rights in any background technology. Maintainers may reject or quarantine a contribution when origin, licensing, security, or clean-room status is uncertain.

Normative changes require an OIAGP Enhancement Proposal, security review when applicable, conformance impact analysis, and maintainer approval under project governance.
